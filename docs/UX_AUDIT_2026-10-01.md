# Rutin UX/UI 全体監査（design.md 準拠）— 2026-10-01

design.md（共通デザイン指針）の全規則に対して、全画面（管理画面・顧客向け・Inbox/チャット・メイト画面・共通部品）をコード監査した結果。機械検査（grep）＋3班の通読監査を統合。**静的監査であり、375px/1280px の実機スクショ・横溢実測は未実施**（「要実測」と記した項目は実機確認してから着手）。

優先度: 【高】=業務実害・誤操作・入力喪失のリスク ／【中】=品質・一貫性 ／【低】=磨き込み。

## 第1部 構造的な根本原因（7つ）— ここを直すと全体の半分近くが解消する

### R1.【高】トーストが部品ごとに独立しており、ダイアログを閉じると成功トーストが消える・モーダルの裏に隠れる
- `useToast()` が部品ローカルの置き場を持つ設計（components/common/Toast.tsx:153-198）。
- **成功トーストが一度も表示されない**: 各ダイアログが `showToast(success)` 直後に `onClose()` → `if (!open) return null` で ToastContainer ごと消える。該当13ファイル: EditPlanDialog / UpsertPlanPriceDialog / UpsertTaxRateDialog / EditStaffDialog / InviteStaffDialog / UpsertLineAccountDialog / UpsertStepMessageDialog / UpsertGiftDialog / UpsertPointProductDialog / EditUserDialog / AssignCastDialog / CreateUserDialog / BulkAssignModal・BulkTagModal（モーダル自身の置き場のため一瞬で消える）。
- **z階層が逆転**: Toast は `fixed bottom-4 right-4 z-50`。解約モーダル（PlanManager.tsx:489, z-50 で DOM 後方）の裏に隠れ、**解約・一時停止・DG 失敗のエラーが顧客に見えない**。スマホのチャットでは送信ボタンの真上に約5秒重なる。
- ToastContainer を useCallback で生成しているため、トースト数が変わるたびに全トースト再マウント（タイマー・Undo カウントダウンがリセット）。role="alert"/aria-live 無し。失敗も成功と同じ5秒で消える。
- → **アプリ全体のトーストプロバイダ（AppShell 直下）に一本化**。z は「通知 > モーダル」。スマホは上部表示。失敗は長め＋見た目分離。文言は「{対象}＋{動詞}」。

### R2.【高】共通 Modal が無く、portal・Esc・bodyロック・閉じるガードが全ダイアログで欠落
- createPortal(document.body) を使うのは Select のみ。tailwind.config.js:91-94 の `fadeIn` が transform を保持するため、`animate-fade-in` の中のモーダルは fixed が壊れる地雷。
- Esc で閉じない（扱うのは MemoSection・CommandPalette・Select・AiDraftButton のみ）。Esc スタック無し → Select を開いた状態の Esc でパネルごと閉じる（InboxFilters.tsx:126-133 × Select.tsx:152-154）。
- body overflow がカウント方式でない。ConfirmDialog.tsx:30-39 は **open=false のマウント時点で `overflow=""`** にし、AppShell の全高固定（AppShell.tsx:44-51）や BulkReviewPanel のロックを外す。CommandPalette.tsx:74-80 も同罪。
- 背景クリックが送信中・dirty でもガードされず入力が消える（EditStaffDialog:170-172 のプロフィール1000字、UpsertLineAccountDialog の11項目＋シークレット、UpsertStepMessageDialog:151 の本文、BulkComposeModal.tsx:41、BulkAiModal も同様）。
- **パスワード表示モーダルが背景クリックで閉じる**（StaffTable.tsx:359-362・InviteStaffDialog.tsx:131-134）—「閉じると再表示できません」なのに誤クリック1回で初期パスワード喪失。
- useKeyboardShortcut.ts:62-111: モーダル開時のページショートカット抑止なし（BulkReviewPanel 上で ⌘K → パレットが裏に開きフォーカスを奪う）。
- → **共通 `<Modal>`**（portal・Esc 多段スタック・ロックカウンタ・初期フォーカス・dirty/submitting 時の閉じるガード＋破棄確認）を作り全置換。

## 第3部 顧客向け画面（申込・マイページ・LIFF）

### 申込フロー【高】
1. **完了画面のトライアル表示が実付与と無関係**（complete/page.tsx:145）: `isTrialEligiblePlan` 判定のため、再契約・追加契約（トライアル無し＝即時課金）にも「7日間の無料トライアルを開始しました」→ **請求表示の誤り**。→ `session.subscription.status==="trialing"` で判定。
2. **満員・受付停止メイトが「見つかりません」**（plan/page.tsx:120-136）: listAvailableCasts が除外するため、直URL・checkoutError=capacity/stopped で戻った人に理由が出ない。→ 停止中でも行を取得し「受付停止中／枠が埋まりました＋他のメイトを見る」。
3. **上限超過エラーが「時間をおいて再度」に誤分類**（lib/subscribe-checkout-errors.ts:24-29）: 「同時にご契約いただけるメイトは3人までです」が generic 扱い。→ limit コード追加・文字列判定をやめる。
4. **追加契約で契約中メイトを選べて必ず失敗**（plan/page.tsx:75）: mode=add でも除外判定なし。一覧も上限3人を見ない。→ plan ページでも excludeContracted＋上限判定、「ご契約中です→マイページ」。
5. **決済キャンセルで選択内容と mode=add が消える**（lib/subscribe-paths.ts:58-60）: cancel_url 固定→追加契約者に新規向け「7日間無料」が出る。→ cancel_url に castId/mode/interval を載せる。
6. **未確認の完了画面が見出しと本文で矛盾**（complete/page.tsx:85-93）: 「契約確認中です」×「確認できませんでした…お問い合わせください」、ボタン無し。→ 再読み込み＋LINEに戻る＋可能ならポーリング。
7. **追加契約完了画面の主ボタン2つ・形不統一**（complete/page.tsx:162-186）: 友だち追加（rounded-full）と LINE に戻る（rounded-md）が両方 primary。addMateFriendUrl 取得失敗時は案内ごと消える。→ 友だち追加を唯一の主ボタン、失敗時は代替手順を表示。
